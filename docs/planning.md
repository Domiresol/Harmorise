# 음악 연습 성장 분석 서비스 기획서

> **서비스명 (가칭):** GrooveLog / Practice Note / PlayTrack

> **작성일:** 2026년 5월 22일

---

## 1. 서비스 개요

**한 줄 소개**
음악 연습 과정을 기록하고, 성장 데이터를 시각화하는 음악 연습 분석 플랫폼

**서비스 목적**
음악 연습은 대부분 기록 없이 반복되기 때문에 사용자는 자신의 성장 과정을 체감하기 어렵다. 본 서비스는 연습 시간, 곡, BPM, 연습 유형 등을 기록하고 시각화하여 사용자가 자신의 성장을 직접 확인하고 꾸준한 연습 습관을 형성할 수 있도록 돕는다.

**핵심 컨셉**
단순한 연습 기록 앱이 아닌 '음악 성장 데이터 플랫폼'

---

## 2. 기획 배경

현재 음악 연습 사용자들이 경험하는 주요 문제:

- 연습 내용을 체계적으로 기록하지 못함
- 성장 여부를 체감하기 어려움
- 연습 루틴이 쉽게 무너짐
- 어떤 부분이 부족한지 객관적으로 보기 어려움
- 메트로놈, 악보, 튜너 앱은 많지만 성장 관리 중심 서비스는 부족함

## 4. 주요 기능

| 기능 | 설명 |
|------|------|
| 연습 기록 | 연습 날짜, 시간, 악기 종류, 연습 곡, 연습 유형 등을 기록 |
| BPM 성장 관리 | 특정 곡 또는 연습 항목에 대한 BPM 변화 기록 및 시각화 |

| 성장 리포트 | 주간/월간 기준 연습 데이터 요약 제공 |

## 5. 서비스 차별점 및 확장 가능성

**차별점**
기존 음악 앱(메트로놈, 튜너, 악보)이 도구 제공에 집중했다면, 본 서비스는 성장 기록과 연습 분석, 습관 관리에 집중한다.

**확장 가능성**

- 커뮤니티 기능 — 연습 기록 공유 및 밴드원 간 진행 상황 공유
- AI 기반 분석 — 연습 패턴 분석 및 맞춤형 루틴 추천
- 오디오 분석 — 템포 안정성 및 리듬 정확도 분석
- 레슨 연동 — 선생님과 연습 기록 공유 및 피드백 기능

## 7. 기술 스택

### 플랫폼 전략

웹 우선 개발 후 WebView 기반 모바일 앱 래핑으로 출시. 데스크탑은 공식 지원하지 않으며, 태블릿 레이아웃을 max-width로 고정하여 데스크탑에서도 동일하게 제공.

### 기술 스택 상세

| 분류 | 기술 | 비고 |
|------|------|------|
| 모노레포 관리 | NX | NestJS 공식 지원, 프론트/백 통합 관리 |
| 백엔드 | NestJS + TypeScript | 2026년 Node.js 백엔드 표준 |
| 프론트엔드 | React + Vite | SPA 구조, WebView 최적화 |
| 스타일링 | Tailwind CSS + shadcn/ui | 디자인 시스템 일관성 확보 |
| 서버 상태 관리 | TanStack Query | |
| 클라이언트 상태 | Zustand | |
| ORM | Prisma | PostgreSQL 완전 지원 |
| 데이터베이스 | PostgreSQL + TimescaleDB | RDBMS, 시계열 확장, BPM 데이터 최적화 |
| 캐시 / 잡큐 | Redis + BullMQ | 비동기 리포트 생성, 스트리크 캐싱 |
| 메시지 브로커 | Kafka (Redpanda) | 연습 이벤트 스트리밍, 데이터 파이프라인 |

### 데이터 파이프라인 구조

연습 기록 저장 시 Kafka 이벤트를 발행하고, 각 컨슈머가 역할별로 독립적으로 처리하는 구조.

```
연습 기록 저장 이벤트 발행 (NestJS Producer)
        ↓
    Kafka 토픽
        ↓
┌─────────────────────────────────────────┐
│  TimescaleDB 시계열 저장 컨슈머          │ → BPM/시간 데이터 적재
│  성장 리포트 집계 컨슈머                 │ → BullMQ 잡 등록 후 비동기 처리
│  알림 발송 컨슈머                        │ → 연습 스트리크, 목표 달성 (추후 확장)
└─────────────────────────────────────────┘
```

### 서버 인프라

| 단계 | 구성 | 비고 |
|------|------|------|
| 로컬 개발 | Docker Compose | PostgreSQL+TimescaleDB, Redis, Redpanda, Redpanda Console |
| 초기 프로덕션 | Railway | 자동 배포, PostgreSQL 포함, GitHub 연동 |
| 스케일업 | AWS EC2 + RDS | 트래픽 증가 시 마이그레이션 |

### 포트폴리오 방향성 (데이터 엔지니어링)

본 프로젝트는 데이터 엔지니어링 포트폴리오를 겸하여, 아래 역량을 직접 구현하고 시연할 수 있도록 설계한다.

- Kafka 기반 이벤트 드리븐 아키텍처 설계 및 구현
- TimescaleDB를 활용한 시계열 데이터 모델링
- BullMQ를 통한 비동기 데이터 처리 파이프라인
- Redis를 활용한 캐싱 전략 및 실시간 통계
- Docker Compose 기반 로컬 분산 시스템 환경 구성

## 8. UX / 디자인 방향

### 지원 화면

| 구분 | 너비 기준 | 레이아웃 |
|------|----------|----------|
| 모바일 (세로) | ~ 767px | 기본 레이아웃 (주력) |
| 태블릿 (가로) | 768px ~ | 확장 레이아웃 |
| 데스크탑 | 768px 이상 동일 | 태블릿 레이아웃 max-width 중앙 고정 |

### UX 원칙

- **빠른 기록** — 연습 기록은 최대한 간단하고 빠르게 가능해야 함
- **즉각적인 성장 체감** — 사용자가 데이터를 통해 발전을 느낄 수 있어야 함
- **부담 없는 사용성** — 복잡한 음악 이론 없이 누구나 쉽게 사용 가능
- **꾸준함 유도** — 서비스 자체가 연습 습관을 유지하게 만드는 구조
- **모바일 퍼스트** — 모든 UI는 모바일 기준으로 먼저 설계

## 9. 법무 검토 사항

**서버 위치 확인 필요**
Railway 기본 서버는 미국 리전. 국내 서비스 대상 시 개인정보보호법 준수 여부 확인 필요. 해외 사용자 포함 시 GDPR 검토 필요.

**오픈소스 라이선스 관리**
사용 라이브러리(NestJS, Prisma, React, shadcn/ui, Redpanda 등) 라이선스 목록 관리 및 서비스 출시 전 검토 필요. 특히 Redpanda는 BSL(Business Source License) 적용으로 상업적 이용 조건 확인 필요.
